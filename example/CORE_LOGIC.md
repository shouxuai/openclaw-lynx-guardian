# OpenClaw Guardian 核心逻辑说明

OpenClaw Guardian 是一个旨在保护 Agent 执行环境安全的插件。它通过拦截高危操作（如命令执行、文件写入），并结合规则匹配与 LLM 意图识别，来决定是否允许操作执行。

## 核心流程

工程入口位于 `index.ts`，其主要工作流程如下：

1.  **拦截 (Intercept)**: 监听 `before_tool_call` 事件。
2.  **筛选 (Filter)**: 仅检查 `exec` (命令执行), `write` (写文件), `edit` (编辑文件) 这三个工具的调用。其他工具直接放行。
3.  **规则匹配 (Blacklist Check)**:
    *   **白名单优先**: 检查命令是否在安全白名单 (`SAFE_EXEC`) 中（如 `git`, `ls`, `cat` 等）。如果是，直接放行。
    *   **黑名单匹配**: 将命令或路径与预定义的黑名单规则进行匹配。
        *   **Critical (严重)**: 系统级破坏操作（如 `rm -rf /`, 修改 `/etc/passwd`, 反弹 Shell 等）。
        *   **Warning (警告)**: 高风险但可能是用户意图的操作（如 `sudo`, `chmod 777`, `rm -r` 非系统目录）。
4.  **意图验证 (Intent Verification)**: 如果命中黑名单，则调用 LLM 判断用户意图。
    *   **Critical 级别**: 需要 **3 次** LLM 投票，且必须 **全部确认** (3/3) 用户明确要求执行该操作，才予以放行。
    *   **Warning 级别**: 需要 **1 次** LLM 投票确认用户意图。
    *   **LLM 决策逻辑**: LLM 会阅读最近的用户对话上下文，判断用户是否明确请求或确认了该操作。
5.  **审计 (Audit)**: 所有命中黑名单的操作（无论放行还是拦截）都会被记录到本地审计日志中。

## 模块详解

### 1. 黑名单机制 (`src/blacklist.ts`)

黑名单规则分为 `CRITICAL` 和 `WARNING` 两个级别，针对 `exec` 和 `file` 操作分别定义。

*   **命令解析**: 支持对 Shell 命令进行分割（按 `;`, `|`, `&&` 等），逐段检查。
*   **Pipe 攻击检测**: 特别检测通过管道 (`|`) 传输的恶意命令（如 `curl ... | bash`）。
*   **上下文感知**: 能够识别并忽略引号或注释中的敏感关键词。

**典型规则示例**:
*   **Critical**:
    *   `rm -rf /` (根目录递归删除)
    *   `mkfs`, `dd` (格式化/破坏磁盘)
    *   修改 `/etc/passwd`, `/etc/shadow`
    *   反弹 Shell (`bash -i`, `nc -e`)
    *   Node/Python/Perl/Ruby 的内联执行 (`-e`, `-c`) 涉及危险操作
*   **Warning**:
    *   `sudo` (提权)
    *   `chmod 777` (放宽权限)
    *   `systemctl stop` (停止服务)
    *   `kill -9` (强制杀进程)

### 2. LLM 投票器 (`src/llm-voter.ts`)

*   **模型选择**: 自动从 OpenClaw 配置中选择性价比高、速度快的模型（优先 `claude-3-haiku`, `gpt-4o-mini` 等）。
*   **Prompt**: 系统提示词要求 LLM 仅判断“用户是否明确请求或确认了此操作”，而不判断操作本身的危险性（危险性由代码规则判定）。
*   **上下文**: 读取最近的 Session 记录（用户消息），作为 LLM 判断的依据。
*   **多重投票**: 对于 Critical 操作，并发调用多次 LLM 进行“多重验证”，降低模型幻觉风险。

### 3. 审计日志 (`src/audit-log.ts`)

*   **存储位置**: `~/.openclaw/guardian-audit.jsonl`
*   **防篡改**: 采用 **Hash Chain** (哈希链) 结构。每条日志包含上一条日志的 Hash 值，确保日志链条的完整性，任何中间篡改都会导致后续 Hash 校验失败。
*   **记录内容**: 时间戳、工具名、黑名单级别/原因、匹配模式、用户是否确认、最终放行/拦截原因、当前 Hash、上一条 Hash。

## 配置策略 (`default-policies.json`)

插件默认启用 (`enabled: true`)。可以通过修改配置文件禁用插件（不推荐）。

## 总结

OpenClaw Guardian 采用 **“规则守底线 + LLM 懂意图”** 的混合防护策略。规则层负责快速过滤已知的绝对危险和高风险模式，LLM 层负责在风险发生时结合上下文进行智能判决，既保证了安全性，又避免了死板的规则误杀用户的合理需求。
